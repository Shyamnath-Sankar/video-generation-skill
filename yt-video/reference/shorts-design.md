# What makes a Short work (write the script with this open)

## The frame
- 1080×1920, 9:16, viewed on a phone held at arm's length, often **muted** (captions carry the story) and often **mid-scroll** (the first second decides).
- **Safe zone** (the Shorts UI covers the rest): keep text and key visuals inside **x 60–940, y 288–1440**.
  - top 288 px: search, menu, progress
  - bottom 480 px: title, channel name, description, subscribe button (long titles climb higher)
  - right 140 px: like / dislike / comment / share / remix stack
- Layout bands: kicker/label y 300–380 · main visual y 380–1150 · captions y 1180–1420 (centre ~1300).
- Type sizes at 1080 wide: hero numbers/words 180–480 px, headings 80–130, labels 40–60, captions 56–112. **Nothing under 34 px** (the checker warns).
- Full-bleed backgrounds can (and should) fill the whole 1080×1920; only *information* stays in the safe zone.

## The structure (20–45 s)
| Beat | Length | Job |
|---|---|---|
| **Hook** | 0–2 s | A claim, number, question or visual that creates a gap. On screen at frame 0. Never "Hi guys", never a logo sting. |
| **Setup** | 2–8 s | The one piece of context needed. |
| **Payoff(s)** | 1–3 scenes | One idea per scene, each with its own visual change on a key word. |
| **Twist / so-what** | optional | Why it matters, the surprising consequence. |
| **Close** | 2–3 s | Land the idea (a callback to the hook loops well) or a follow CTA. Don't ask for likes before delivering. |

Loop trick: if the last line leads back into the first ("…and that's why your brain is only 2%"), replays count.

## Pacing
- Something visibly changes every **1–2 s**; a new scene every **3–6 s**. The verifier flags 3 s+ with no motion.
- 2.5–3 spoken words per second; about 80 words for 30 s.
- Each visual change lands on the **spoken word** it illustrates (`K.cue`), slightly early (0.05–0.1 s).
- Hard cuts only where the style allows (`punch`); otherwise objects carry the eye across scene changes.

## Captions
- Always on unless the style is `off` by design. 1–3 words per page for energetic styles, up to 6 for calm ones.
- The active word is highlighted in the accent colour. Numbers as digits in captions (`20%`) even when spoken as words.
- Captions never cover the main visual: the visual sits above y 1150.

## Content honesty
- Never invent facts, statistics, quotes, prices, results or user counts. If the user didn't give a number and you can't verify it, use relative visuals (bars without values, "more/less") or ask.
- Example content inside mockups (a file name, a command, an IP, a project name) is fine: list it as illustrative in the delivery note.
- No third-party logos or characters unless the user supplies them and has the right to use them.

## Checklist before approval
- [ ] Hook works with the sound off, from frame 0
- [ ] One idea per scene, each with a named cue word
- [ ] Under 60 s (or the user asked for longer, max 180 s)
- [ ] Every number is sourced from the user or a source you can name
- [ ] The last line lands the point (or loops)
